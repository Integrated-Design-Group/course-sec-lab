# 09 · 漏洞验证方法模板

> **适用对象**：验证执行人、证据整理人、指导教师
> **前置条件**：已完成 [08-vuln-design.md](./08-vuln-design.md) 的设计评审；已获得测试窗口授权；已备份靶场数据
> **预计耗时**：单个漏洞验证 30～60 分钟；整理证据与报告 30 分钟

## 0. 使用说明

本文件是**模板**，不是已完成的验证报告。`VERIFY-VULN-01-01`～`VERIFY-VULN-05-01` 已于 2026-11-26 在课程授权云服务器的独立容器/端口上完成 loopback 验证；验证结果见 [08-vuln-design.md](./08-vuln-design.md) 第 8 节与 [14-vuln-branch-isolation-check.md](./14-vuln-branch-isolation-check.md)。证据只保留在课程本地/课程平台，未提交攻击载荷。

- 复制第 3 节的记录模板，逐字段填写；**未执行的项必须写“未验证”及原因**。
- 验证只在独立靶场、约定窗口、约定来源 IP 内进行。

## 2. 通用验证流程

```text
① 记录基线（正常请求的响应/数据）
② 按设计构造最小验证请求（只验证存在性，不扩大影响）
③ 观察响应 / 日志 / 数据库变化
④ 截图与保存原始请求响应（脱敏）
⑤ 按判定标准给出结论
⑥ 清理数据、关闭开关、恢复基线
⑦ 复测（修复后）与归档
```

## 4. 各漏洞验证骨架（设计，不含攻击载荷）

> 以下只描述“验证思路与判定点”。具体输入必须在授权靶场中按最小影响原则构造，**不得写入仓库**。

### 4.1 `VERIFY-VULN-01-01` 登录注入

- 前置：`VULN_MODE=VULN-01`，测试账号可用。
- 步骤：基线登录 → 构造能改变查询语义的最小输入 → 观察认证结果与日志 → 检查数据库是否被读取/篡改。
- 判定：认证被绕过或数据可被读取 → 漏洞存在；仅返回参数错误 → 不成立。
- 清理：重置数据库，关闭开关。
- 修复回归：参数化后同一输入应返回 `AUTH_INVALID_CREDENTIALS`，且日志无 SQL 报错。

### 4.2 `VERIFY-VULN-02-01` 存储型 XSS

- 前置：M1 条目写入能力已具备（A-02/A-05）；`VULN_MODE=VULN-02`。
- 步骤：用测试账号写入含脚本语义的内容 → 用另一账号打开详情页 → 观察是否被执行 → 检查 DOM 与会话状态。
- 判定：脚本在受害者浏览器执行 → 存在；仅作为纯文本显示 → 不成立。
- 清理：删除测试条目，重置种子。
- 修复回归：内容应被转义显示，CSP 拦截内联脚本。

### 4.3 `VERIFY-VULN-03-01` 水平越权

- 前置：学生 A / 学生 B 各有一条条目。
- 步骤：用 A 的令牌请求 B 的资源详情/编辑 → 对比响应与数据库变化。
- 判定：可读取或修改 B 的数据 → 存在；返回 403/404 → 不成立。
- 清理：恢复被修改的测试数据。
- 修复回归：服务端校验 `owner_id`，返回 403；管理员按设计放行。

### 4.4 `VERIFY-VULN-04-01` 不安全上传

- 前置：`VULN_MODE=VULN-04`；上传目录的刻意错误配置已生效。
- 步骤：按设计尝试上传不被允许的类型/内容 → 检查落盘位置、文件名、可访问性、数据库中记录。
- 判定：可落盘到非预期位置或可被直接访问/执行 → 存在；被 415/413 拒绝且无残留 → 不成立。
- 清理：删除测试文件，重置上传目录。
- 修复回归：白名单 + 文件头校验 + 随机名 + 非 Web 根，返回结构化错误。

### 4.5 `VERIFY-VULN-05-01` 认证缺陷

- 前置：`VULN_MODE=VULN-05`；限流策略按设计放宽。
- 步骤：多次失败登录观察限流 → 退出后复用旧令牌 → 检查令牌过期行为与日志。
- 判定：可无限尝试或旧令牌仍有效 → 存在；触发 429/401 → 不成立。
- 清理：清除失败计数（重启或等待窗口），关闭开关。
- 修复回归：429 生效、退出后 401、过期后 401。

## 5. 证据规范

1. **原始性**：保存原始请求/响应文本（curl `-i` 或浏览器导出），不只保留截图。
2. **可复现**：记录时间（UTC）、目标、账号角色、`VULN_MODE`、数据版本。
3. **脱敏**：token 只保留前 8 位、密码不出现、IP 可打码、个人信息替换为占位。
4. **完整性**：每个结论至少 1 条请求响应 + 1 条观察证据（日志/数据库/截图）。
5. **存放**：`evidence/verify-vuln-0x-yy/`（该目录已被 `.gitignore` 忽略；归档按课程要求单独提交）。

## 6. 判定标准

| 结论 | 条件 |
| --- | --- |
| 通过（漏洞存在） | 按设计复现，证据完整，影响清晰，且未超出测试数据范围 |
| 不通过（未复现） | 多次尝试仍无法触发；或触发但属于预期安全行为（如参数化拦截） |
| 阻塞 | 环境/账号/开关问题导致无法验证，必须写明原因与后续计划 |
| 误报 | 表面异常但经核查为正常行为（如错误码差异属设计） |

## 7. 复测与回归

- 修复后必须用**同一用例**复测，并记录“修复前/修复后”对比。
- 复测需重新执行 `bash scripts/seed.sh` 保证数据一致。
- 回归范围：本漏洞 + 相邻接口（如修复登录注入后回归登录限流与正常登录）。
- 结论更新到 [08-vuln-design.md](./08-vuln-design.md) 状态表。
