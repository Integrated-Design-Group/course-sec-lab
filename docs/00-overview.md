# 00 · 项目总览与范围

> **适用对象**：课程小组成员、指导教师、验收人
> **前置条件**：已阅读课程要求；本地具备 Node.js 22+（或 Docker）
> **预计耗时**：阅读 10 分钟

## 1. 这是什么

**course-sec-lab（课程 Web 安全靶场）** 是一个课程小组自主设计的 Web 管理系统，当前处于 **M1 完成 / M2 漏洞分支已实现并验证 / M3 已部署** 阶段。

- 业务场景：**校园二手教材交易平台**——学生发布闲置教材/笔记，管理员维护平台内容。
- 当前交付：主站（M1）、`vuln/ALL` 全量靶场分支（默认 `VULN_MODE=ALL`，仅课程内网）、云服务器主站部署（HTTP 8080）、B-09 验证结果、完整漏洞清单/验证方法。
- 已交付环境：课程授权 Ubuntu 24.04 服务器；真实 IP 只登记课程平台，不写入仓库。
- 明确不交付：第三方扫描系统对接、教师签字、真实 HTTPS 证书（用户选择暂不需要）。

## 2. 为什么选择这个业务场景

| 维度 | 说明 |
| --- | --- |
| 业务真实 | 校园二手交易是学生熟悉的真实场景，答辩时容易讲清“谁在用、解决什么问题” |
| 结构完整 | 天然包含用户、角色、资源（条目）、文件（封面图）、审计（操作记录） |
| 漏洞可设计 | 登录、列表筛选、详情、上传等入口可以自然映射到 3～5 类典型 Web 漏洞 |
| 数据可脱敏 | 全部使用假数据，不涉及真实学生个人信息与支付信息 |
| 范围可控 | 业务模型简单，能在课程周期内完成“框架 → 业务 → 漏洞 → 部署 → 验证”闭环 |

## 5. 阶段边界（M0 → M1）

### 5.1 M0 框架阶段（已完成）

- 目录与工程骨架、依赖锁定、环境变量模板
- 数据库：`roles`、`users`、`business_items`、`uploaded_files`、`audit_logs` 表 + 迁移 + 种子
- 后端：配置校验、统一响应、错误码、结构化日志、健康检查、认证闭环、只读业务接口、安全上传基线
- 前端：路由、布局、登录页、API Client、路由守卫、健康检查展示
- 部署：Compose 编排、Nginx 配置、部署/回滚脚本
- 文档：架构、数据库、API、部署、环境、规范、隔离、漏洞模板、验证模板、访问登记、验收清单

### 5.2 M1 业务阶段（已完成，2026-11-18）

- 业务条目 **CRUD**：创建 / 编辑 / 软删除，归属校验（本人或 admin）、状态机、乐观并发（`expectedUpdatedAt`）、审计
- 列表增强：“我的条目”过滤、稳定排序、迁移 002 索引
- 封面：上传后绑定 `coverFileId`；**受控鉴权读取**（本人 / 管理员 / 条目封面引用）；替换或删除后归档孤儿封面
- 管理端：用户列表 / 启用停用（禁止停用自己、禁止停用最后一个管理员）、审计日志检索
- 前端：新建/编辑表单、详情封面与操作按钮、管理后台三个面板
- 种子 002：8 条演示条目，覆盖 5 种状态与 2 个所有者
- 测试：后端 44 项、冒烟 6 项、API 契约 11 项全部通过（校验细节见 [framework-acceptance.md](./framework-acceptance.md) 附录与 [13 交付流程](./13-m1-delivery-runbook.md)）

### 5.3 仍未做

- **不实现 main 分支漏洞**：`main` 没有 SQL 注入、XSS、越权、不安全文件上传、弱认证等**可利用**缺陷；VULN-01～VULN-05 已在独立 `vuln/*` 分支实现，默认 `VULN_MODE=off`，不合并 main。
- 已在课程授权云服务器完成主站部署（HTTP 8080，无域名/HTTPS）；未创建新的付费云资源
- 不写入真实密码、云密钥、证书私钥或任何敏感数据到仓库；真实值只在部署机 `.env`/课程平台
- 不做性能压测、不做多副本高可用（单机课程版）
- 已知边界：草稿条目当前对游客可见；上传文件不提供公开 URL；JWT 撤销表与限流为进程内实现；演示账号暂保留（用户已确认接受风险）

> 漏洞的**设计**在 [08-vuln-design.md](./08-vuln-design.md) 中已冻结；B-02～B-06 已在 `vuln/*` 分支实现，B-10 完成本地隔离/有效性检查；B-09 仍需在授权独立实例复现。

## 7. 关键约定（全项目）

1. **API 前缀固定** `/api/v1`；成功/失败都使用统一响应信封（见 [03-api.md](./03-api.md)）。
2. **时间统一存 UTC**（数据库 `DATETIME(3)`，API 返回 ISO 8601），前端按本地时区展示。
3. **密钥只进 `.env`**；`.env.example` 只放占位符。仓库内出现真实密钥即视为不合格。
4. **演示账号** `admin` / `student`，密码 `Demo@123456`，仅课程环境使用，公网部署前必须改密或停用。
5. **所有“未实现”必须显式失败**（404 / 501），不允许返回假的成功结果；M1 起写接口均已实现，`NOT_IMPLEMENTED` 仅作为保留错误码。

## 9. 安全与合规声明

本靶场**只用于课程授权范围内的安全测试**：

- 必须独立部署，不得与真实业务系统共用主机、数据库、域名或账号；
- 存放的数据必须是课程假数据，不得导入真实个人信息；
- 任何测试必须在约定时间窗口、约定来源 IP 内进行；
- 未获得课程负责人书面（含课程平台）授权，不得对任何非本项目目标进行测试。
