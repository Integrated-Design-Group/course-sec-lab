# 07 · 隔离与授权规范

> **适用对象**：项目负责人、部署负责人、所有参与测试的成员
> **前置条件**：已阅读 [00-overview.md](./00-overview.md)；已获得课程负责人对靶场范围的确认
> **预计耗时**：阅读 15 分钟；落实隔离清单约 30 分钟

## 0. 总则（必须遵守）

> **本靶场必须独立隔离部署，仅用于课程授权范围内的安全测试。**
>
> - 不得部署在与真实业务共用的主机、数据库、域名或账号体系上。
> - 不得对非本项目目标（学校任何真实系统、第三方网站、公网任意主机）进行扫描或攻击。
> - 不得在靶场中存放真实学生信息、真实交易数据、真实凭据。
> - 测试必须限定在约定时间窗口与约定来源 IP 内。
> - 发现任何越界迹象（异常外联、数据泄露、影响他人）应立即停止并上报。

## 1. 隔离原则

| 原则 | 含义 | 落地要求 |
| --- | --- | --- |
| 资源独立 | 靶场独占计算、存储、网络资源 | 独立云主机/实例，独立数据卷 |
| 网络隔离 | 靶场不能横向访问其他系统 | 独立 VPC/子网或独立安全组；数据库无公网 |
| 数据隔离 | 只有课程假数据 | 种子数据 + 造数，禁止导入真实数据 |
| 账号隔离 | 靶场账号与个人账号分离 | 专用 DB 账号、专用 SSH 密钥、专用测试账号 |
| 时间隔离 | 测试只在窗口内进行 | 记录窗口，窗口外关闭或限制访问 |
| 可销毁 | 可一键下线且不留残留 | 容器化部署 + 命名卷 + 下线清单 |

## 2. 资源隔离清单

| 资源 | 要求 | 验收方式 |
| --- | --- | --- |
| 云主机 | 独立实例，仅本项目使用；标签/备注注明“课程靶场” | 云控制台截图（脱敏） |
| 网络 | 独立 VPC 或独立子网；不与其他业务对等互联 | VPC/子网配置页 |
| 安全组 | 入站仅 80/443 + SSH 白名单；禁止 3000/3306 | 安全组规则截图 |
| 数据库 | 容器内 MySQL 或独立实例；**无公网地址**；仅 backend 可连 | `docker compose ps`、连接测试 |
| 对象/文件存储 | 仅 Docker 卷或独立目录；不与他人共享 | 卷列表 |
| 域名（可选） | 独立子域名，如 `{{DOMAIN}}`；不复用业务域名 | DNS 记录 |
| 代码仓库 | 本课程仓库；漏洞代码只在 `vuln/*` 分支 | 分支列表 |

## 3. 账号与凭据隔离

| 项 | 要求 |
| --- | --- |
| 云账号 | 使用课程负责人提供的账号或独立子账号；不共享个人主账号 |
| SSH | 每人独立密钥；禁止共享私钥；离职/退课即移除公钥 |
| 数据库 | 应用使用 `lab_user`（仅本库权限），root 仅初始化/备份使用 |
| 应用账号 | 演示账号仅课程使用；测试账号一人一号，便于审计 |
| 密钥保管 | `.env` 权限 600，仅部署负责人持有；不写入文档、聊天记录、截图 |
| 泄露处置 | 立即轮换 → 清理历史 → 记录事件 |

## 4. 网络隔离

```text
公网 ──[安全组: 80/443 + SSH 白名单]──> web(Nginx)
                                          │ 容器网络 app_net
                                          ▼
                                      backend(Node)
                                          │ 容器网络 internal（无外网出口）
                                          ▼
                                        db(MySQL)
```

- 数据库端口**不映射宿主机**、**不加入安全组放行**。
- `internal` 网络 `internal: true`，数据库无外网出口（不能外联下载/回连）。
- 后端容器同时接入 `app_net` 与 `internal`，只暴露 3000 给 web。
- 上传文件不放在 Web 根目录，也不提供公开静态 URL；读取走 `GET /api/v1/uploads/:id`，需登录且满足“本人 / 管理员 / 该文件被未删除条目用作封面”之一。
- 如需从外部调试数据库，使用 SSH 隧道 + 临时放行，用完立即关闭并记录。

## 5. 数据隔离

- 只使用 `db/seeds/` 中的课程假数据与自行构造的假数据。
- 姓名、学号、手机号、邮箱等使用虚构值（如 `student@example.edu`），域名使用 `example.edu`。
- 不上传真实证件、成绩单、聊天记录截图。
- 演示结束或下线时销毁数据库与上传卷（见第 9 节）。

## 6. 授权范围与测试窗口

| 项 | 内容 |
| --- | --- |
| 授权方 | 课程负责人 / 指导教师（以课程平台或书面通知为准） |
| 授权对象 | 仅本项目的公网地址 `{{PUBLIC_IP}}` 或 `{{DOMAIN}}` |
| 授权时间 | `{{TEST_WINDOW_START}}` ～ `{{TEST_WINDOW_END}}`（按周/按次约定） |
| 来源限制 | 仅 `{{TEST_WINDOW_CIDR}}` 可访问（安全组白名单） |
| 允许动作 | 按 `docs/08` 设计的漏洞验证；只做**读取/最小影响**的证明 |
| 禁止动作 | 拒绝服务、批量拖库、持久化后门、横向移动、攻击他人系统、公开披露 |
| 数据处理 | 证据脱敏；不保存真实个人信息；结束后删除或归档到课程指定位置 |

> 访问信息统一登记在 [10-access.md](./10-access.md)，**不得写入真实值到本仓库**。

## 7. 漏洞研究的额外隔离（M2 阶段）

漏洞实现与验证必须在满足以下条件后才能开始：

1. **独立分支** `vuln/VULN-0x`，禁止合入 `main`。
2. **独立实例**（独立目录/独立端口/独立数据库），不与框架演示实例共用。
3. **显式开关**：全量分支 `vuln/ALL` 默认 `ALL`（5 个同时开启，仅课程内网）；单漏洞分支默认关闭；启动日志必须打印当前模式。
4. **可一键恢复**：保留 `scripts/seed.sh` 重置能力，测试后可回到无漏洞状态。
5. **限定时限**：测试窗口结束即销毁实例与数据。
6. **教师知情**：开始前向课程负责人报备测试计划与时间。

## 8. 监控与审计

| 层面 | 手段 |
| --- | --- |
| 应用 | `audit_logs` 记录登录成功/失败、上传、后续的写操作 |
| 访问日志 | Nginx stdout（`docker logs csl-web`） |
| 容器 | `docker compose logs`、健康检查状态 |
| 云侧 | 安全组流量日志（若云厂商支持）、登录审计 |
| 巡检 | 每日检查一次异常登录/异常流量；测试窗口结束后复盘 |

## 9. 下线流程

> 顺序不可颠倒：先切断访问 → 再备份 → 再销毁 → 最后归档。

1. **通知**：在课程群通知测试结束，停止一切测试流量。
2. **切断访问**：安全组移除 80/443 规则（或 `docker compose stop web`）。
3. **备份留档**：`mysqldump` + uploads 打包 + 关键日志（按课程要求保存或直接销毁）。
4. **停止服务**：`docker compose -f deploy/docker-compose.yml --env-file .env down`（**不要加 `-v`**）。
5. **销毁数据卷**：确认备份完成后 `docker volume rm course-sec-lab_db_data course-sec-lab_upload_data course-sec-lab_app_logs`。
6. **删除容器镜像**：`docker image rm` 本项目镜像（可选）。
7. **释放云资源**：删除实例、弹性 IP、安全组、VPC（按课程要求）。
8. **清理凭据**：轮换/删除数据库密码、JWT 密钥、SSH 公钥、演示账号。
9. **归档**：漏洞清单、验证记录、部署记录、下线记录归档到课程指定位置。
10. **确认**：在 [10-access.md](./10-access.md) 记录下线时间与执行人。

## 10. 事故响应

| 情况 | 立即动作 | 后续 |
| --- | --- | --- |
| 发现靶场被非授权访问 | 切断 80/443，保留日志 | 上报教师，分析来源，轮换全部凭据 |
| 测试造成数据损坏 | 停止测试，按备份恢复 | 记录事件，复盘中补保护措施 |
| 误对非目标发起测试 | 立即停止，保存请求记录 | 主动上报教师，评估影响 |
| 密钥疑似泄露 | 轮换密钥、重启服务 | 清理仓库历史，记录处置过程 |
