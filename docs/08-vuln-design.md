# 08 · 漏洞设计与清单（框架阶段：仅设计，不实现）

> **适用对象**：负责漏洞设计与验证的成员、指导教师
> **前置条件**：已阅读 [07-security-isolation.md](./07-security-isolation.md)；框架阶段验收通过
> **预计耗时**：阅读 15 分钟；完成 3～5 个漏洞的设计评审约 60 分钟

## 0. 当前状态（重要）

> **框架阶段未实现任何漏洞。** 本文件只定义编号规则、清单字段与 5 个候选漏洞的**设计占位**。
>
> 代码中**不存在** SQL 注入、XSS、越权、不安全文件上传、弱认证等可利用缺陷；上传接口已具备类型/签名/大小校验，SQL 全部参数化，接口均有认证与统一错误处理。
>
> 任何漏洞实现都必须：独立分支 + 独立实例 + 显式开关 + 教师知情 + 测试后销毁（见 [07-security-isolation.md](./07-security-isolation.md) 第 7 节）。

## 1. 编号规则

| 规则 | 说明 |
| --- | --- |
| 格式 | `VULN-01` ～ `VULN-05`（两位数字，短横线） |
| 预留 | 本项目预留 5 个编号，本次仅使用 01～05 |
| 唯一性 | 编号一经分配不得复用；废弃需登记“已下线”并保留原编号 |
| 扩展 | 如需第 6 个漏洞，必须经指导教师同意后启用 `VULN-06`，并同步更新本文档 |
| 与用例关系 | 每个漏洞对应一个或多个验证用例（`VERIFY-VULN-0x-yy`），用例模板见 [09-verify-template.md](./09-verify-template.md) |

## 2. 漏洞清单字段规范

| 字段 | 必填 | 说明 |
| --- | :---: | --- |
| 编号 | 是 | `VULN-0x` |
| 名称 | 是 | 中文短语，如“登录处 SQL 注入” |
| 类别 | 是 | OWASP Top 10 或通用分类 |
| 风险等级 | 是 | 高 / 中 / 低（依据影响与利用难度） |
| 受影响端点 | 是 | 方法 + 路径 |
| 受影响角色 | 是 | 游客 / 学生 / 管理员 |
| 前置条件 | 是 | 需要的账号、数据、开关状态 |
| 触发方式（设计） | 是 | 高层描述，**不写可直接复用的攻击载荷** |
| 预期影响 | 是 | 数据泄露/篡改/越权/执行等 |
| 检测方法 | 是 | 观察点（响应差异、日志、数据库变化） |
| 修复建议 | 是 | 参数化、转义、鉴权、白名单等 |
| 验证用例 | 是 | 对应 `VERIFY-*` 编号 |
| 状态 | 是 | 见第 3 节枚举 |
| 负责人 | 是 | 成员姓名/代号 |
| 备注 | 否 | 限制、依赖、风险 |

## 6. 开关设计建议

```text
# .env（仅靶场实例使用，禁止出现在 main 分支的部署配置中）
VULN_MODE=off            # off | VULN-01 | VULN-02 | ...
```

要求：

- 默认 `off`；非 `off` 时启动日志打印醒目警告，健康检查返回中也标注当前模式。
- 同一实例同一时刻只开启一个漏洞，避免实验相互干扰。
- 开关只影响后端行为，前端不感知，避免“按开关写死判断”的假漏洞。

## 7. 明确禁止

1. 禁止在 `main` 分支或框架演示实例中实现漏洞。
2. 禁止把漏洞代码、利用载荷、真实目标地址提交到仓库或公开渠道。
3. 禁止对课程之外的任何系统进行测试。
4. 禁止使用真实个人信息、真实凭据进行验证。
5. 禁止在验证中使用拒绝服务、批量拖库、持久化后门等超出课程授权的手段。
6. 禁止在未备份的情况下执行可能破坏数据的验证。
